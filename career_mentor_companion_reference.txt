================================================================================
WHAT IS THE PROJECT?
================================================================================
An AI-powered web application that acts as a personal interview coach
for the Data Science domain. Candidates select a role, experience level,
and interview type. The system generates tailored questions, records their
spoken answer, transcribes it, evaluates it, measures their confidence
from audio signals, generates personalized feedback, and shows everything
on a performance dashboard.

Domain: Data Science only (Data Analyst, Data Engineer, MLOps Engineer,
        BI Developer, Analytics Engineer)
Type:   Practice & self-improvement tool — NOT a recruitment decision tool


================================================================================
PROBLEM BEING SOLVED
================================================================================
- Students and graduates underperform in interviews not due to lack of
  knowledge but lack of practice and timely feedback.
- Existing resources (question banks, YouTube, peer practice) are static,
  general, and give no objective feedback on answers or speaking style.
- Human mock interview coaches are expensive, unavailable on-demand,
  and inconsistent.
- No single open-source system combines: role-specific questions +
  semantic answer evaluation + audio confidence analysis + dashboard.


================================================================================
OBJECTIVES
================================================================================
1. Build an AI mock interview system that generates role-specific questions,
   converts spoken answers to text, and evaluates content + confidence.
2. Provide automated, personalized feedback and performance scores that
   help candidates measurably improve their interview skills.

MODULE-BY-MODULE BREAKDOWN
================================================================================

--- MODULE 1: QUESTION GENERATION ---
How:   LLM with structured prompt engineering
Input: Role + Experience Level + Interview Type (selected by user)
Output: Set of tailored questions + reference answers (stored in PostgreSQL)

Prompt structure:
  "Generate N [technical/HR] interview questions for a [level] [role].
   Cover competency areas: [list]. Return JSON with question + reference answer."

Difficulty calibration:
  Fresher  → Conceptual definitions ("What is overfitting?")
  Junior   → Application ("How do you handle class imbalance?")
  Mid      → Trade-off/design ("Compare SMOTE vs cost-sensitive learning")
  Senior   → Architecture ("Design a real-time fraud detection ML pipeline")

Competency taxonomy (example — Data Scientist):
  Statistics & Probability | ML Algorithms | Feature Engineering |
  Model Evaluation | Python/SQL | Communication of Insights

Deduplication: Cosine similarity on question embeddings prevents repeats.

Database model (PostgreSQL):
  Questions table — id, role, topic, subtopic, difficulty, question_type,
                    question_text, ideal_answer, keywords, code_expected,
                    verified, times_asked, created_at

Data seed sources (reliable, open-source):
  1. github.com/youssefHosni/Data-Science-Interview-Questions-Answers
     (~200 Q&A: ML, DL, Statistics, Probability, Python)
  2. github.com/alexeygrigorev/data-science-interviews
     (~150 Q&A: Theory + SQL + Coding)
  3. github.com/iamtodor/data-science-interview-questions-and-answers
     (~100 Q&A: General DS concepts)
  4. github.com/kojino/120-Data-Science-Interview-Questions (120 Q&A)
  5. kaggle.com/datasets/die9origephit/data-science-interview-questions
  + LLM-generated questions for role gaps (marked verified=False)
  Total estimated seed: ~770 reliable questions

WHY Hugging Face over OpenAI for question generation:
  - Free, open-source, no per-request API cost
  - Flan-T5-Large is instruction-tuned on 1,836 tasks — perfect for prompts
  - Consistent with feedback generation (same model, same stack)
  - For production at scale: OpenAI GPT-4 could be reconsidered


--- MODULE 2: SPEECH-TO-TEXT ---
Tool:  OpenAI Whisper (open-source, free)
Model: Trained on 680,000 hours of weakly supervised multilingual audio
Input: Candidate's recorded audio (WAV/MP3)
Output: Accurate text transcript + word-level timestamps
Why Whisper: Handles accents, background noise, varied speech — robust ASR
Paper: Radford et al., 2022 — arXiv:2212.04356 (already cited in report)


--- MODULE 3: ANSWER EVALUATION ---
Tools: Sentence Transformers (SBERT) + spaCy

Step 1 — Semantic Similarity (SBERT):
  - Candidate transcript → SBERT embedding vector
  - Reference answer → SBERT embedding vector
  - Cosine similarity computed between the two vectors
  - Score 0.85-1.0 = Excellent | 0.65-0.84 = Good | <0.45 = Poor
  - Why SBERT not plain BERT: BERT needs both sentences fed together
    (50M inference ops for 10K pairs = 65 hours). SBERT reduces to 5 seconds.
  - Paper: Reimers & Gurevych, EMNLP 2019 — arXiv:1908.10084

Step 2 — Keyword Coverage (spaCy):
  - Tokenization + POS tagging + NER on transcript
  - Match against curated keyword bank for the question
  - Keyword Score = (matched keywords / total expected keywords) × 100

Step 3 — Completeness Score:
  - Sentence segmentation checks if answer covers all required sub-components
  - (definition, example, use case, limitation, etc.)

Final Technical Score:
  = 0.5 × Semantic Score + 0.3 × Keyword Score + 0.2 × Completeness Score

Reference answer source: Generated by Flan-T5 at question creation time,
  stored in PostgreSQL alongside the question. Retrieved at eval time.


--- MODULE 4: CONFIDENCE ANALYSIS ---
Tool: Librosa (Python audio analysis library)

Feature 1 — Speaking Pace (WPM):
  duration = librosa.get_duration(y=y, sr=sr)
  WPM = (word count from Whisper / duration in seconds) × 60
  Ideal: 120–160 WPM | Too slow <100 = hesitant | Too fast >180 = anxious

Feature 2 — Pause Detection:
  intervals = librosa.effects.split(y, top_db=30)
  Extracts: pause count, average pause duration, silence ratio
  Interpretation: frequent long pauses → unsure; natural short pauses → normal

Feature 3 — Filler Word Detection:
  Whisper provides word-level timestamps → count "um", "uh", "like",
  "you know", "basically" in transcript
  Filler rate = (filler count / total words) × 100
  Ideal: < 2% | Poor: > 5%

Confidence Score = 0.3 × Pace Score + 0.4 × Pause Score + 0.3 × Filler Score
  (each sub-score normalized to 0–100)

Research backing: Naim, Tanveer, Gildea, Hoque (2018) — IEEE Transactions
  on Affective Computing — validated that speaking rate, filler words, and
  pauses correlate with interview performance ratings (r = 0.75+)


--- MODULE 5: FEEDBACK GENERATION ---
Tool: Hugging Face Flan-T5-Large (same model as question generation)

How it works:
  1. Scores from modules 3 & 4 are combined into a structured prompt
  2. Prompt sent to Flan-T5-Large via Hugging Face Inference API or local
  3. Model generates personalized, natural-language feedback text

Example prompt:
  "You are an expert interview coach for Data Science roles.
   Candidate answered: [QUESTION]
   Their answer: [TRANSCRIPT]
   Technical score: 78/100 (missing keyword: error handling)
   Confidence score: 65/100 (3 filler words, 2 long pauses)
   Generate specific, actionable 2-3 sentence feedback."

Example output:
  "Your explanation of ETL pipelines was clear. Strengthen it by discussing
   error handling and idempotency in production pipelines. Try to reduce
   filler words and pause frequency to boost confidence perception."

Why not templates: Templates give same feedback for same score regardless
  of what the candidate actually said. Flan-T5 reads the actual answer and
  generates unique, context-aware advice.
Why not OpenAI GPT-4: Costs $0.02-0.05 per generation. Flan-T5 is free.
  95% of the quality at 0% of the cost — right choice for student project.
Time: 1-3 seconds per answer — practical for real-time dashboards.


--- MODULE 6: SCORING & DASHBOARD ---
Tools: Pandas, NumPy, Scikit-learn (backend) + Recharts (frontend)

Four scores displayed:
  1. Overall Score     = weighted average of all components
  2. Technical Score   = from answer evaluation (SBERT + spaCy)
  3. Confidence Score  = from audio analysis (Librosa)
  4. Communication Score = clarity, fluency, sentence structure

Dashboard features:
  - Per-question breakdown with feedback
  - Score history to track improvement over sessions
  - Interactive charts (Recharts)
  - Strengths and areas for improvement summary

================================================================================
KEY DECISIONS MADE (from project discussions)
================================================================================

Q: Which model for question generation — HF or OpenAI?
A: LLM for question generation, Hugging Face Flan-T5-Large for feedback.
   Unified stack. Free. Instruction-tuned. Consistent architecture.

Q: What is the source of reference answers?
A: Generated by Flan-T5 at question creation time using structured prompt.
   Stored in PostgreSQL alongside each question. Retrieved at eval time.

Q: How does answer evaluation work?
A: Three-component composite: SBERT cosine similarity (50%) + spaCy keyword
   coverage (30%) + completeness score (20%).

Q: How does Librosa measure confidence?
A: Three audio features: speaking pace (WPM), pause frequency/duration,
   and filler word rate. Each normalized 0-100 and weighted into one score.

Q: How does Flan-T5 generate feedback?
A: Takes a structured prompt containing the question, transcript, and all
   numeric scores → generates unique natural-language coaching advice.
   Not a template. Different output for every candidate's unique answer.

Q: Where to get seed question data?
A: Primary: github.com/youssefHosni + github.com/alexeygrigorev +
            github.com/iamtodor + github.com/kojino (total ~770 Q&A)
   Secondary: Kaggle DS interview dataset
   Gap-filling: Flan-T5 generated (marked verified=False in DB)

Q: Why not use exact matching for answer evaluation?
A: Exact matching fails for semantically identical but differently worded
   answers. SBERT understands meaning — "ML workflow" and "machine learning
   pipeline" score high similarity despite different words.

Q: Is this a replacement for human interviewers?
A: No. Explicitly a practice and self-improvement tool. Not for actual
   recruitment decisions.
